# B2 — Controlled variance conditioning

B2 adds a profile loader and prompt integration for existing generation agents.
It does not add graph nodes, agents, batch execution, optimization or repairs.

## Single generation

```powershell
python -m agentic_web generate `
  --workflow collaborative `
  --task tasks/generated/personal_site.json `
  --decomposition tasks/generated/personal_site_tasks.json `
  --variance-condition layout_variance `
  --variance-profile experiments/profiles/layout_exploration.json `
  --output runs
```

All existing model, sampling and resource flags remain available. For a control
generation omit both variance flags, or specify `--variance-condition control`
without a profile. A non-control condition requires a profile; a control condition
with a profile is rejected, avoiding silently mislabeled treatments. The B1 pilot's
unbound non-control labels remain valid planning factors, but must be bound to a
profile in a new experiment configuration before execution. Existing B1 plans
and their candidate IDs have not been changed.

## Profile format

```json
{
  "schema_version": "1.0",
  "profile_id": "my-exploration",
  "dimensions": ["information architecture", "visual hierarchy"],
  "directive": "Compare plausible groupings and reading sequences for the required content, then select a coherent solution within the choices left open by the task.",
  "role_guidance": {
    "ux": "Evaluate discoverability and keyboard interaction across the plausible arrangements."
  }
}
```

`VarianceProfile` rejects extra fields, unsupported versions, blank directives,
empty/duplicate dimensions and unsupported role names. Dimensions are extensible
strings; supported role keys are planner, ux, architect, coordinator, implementer.
The identifier denotes the profile; different condition labels may reference the
same profile. The loader does not maintain a global identifier registry: the hash
distinguishes changed content under an identifier. Examples are
`experiments/profiles/layout_exploration.json` and
`experiments/profiles/architecture_exploration.json`.

## Injection and authority

After task intake/decomposition, `task_loader` validates and snapshots the selected
profile before model availability queries or resource setup. A1 and A3 receive no
variance guidance. Planner and Implementer append a separate experimental section
to their existing system prompt immediately before request logging. The shared
collaboration request builder applies the same mechanism to UX, Architect and
Coordinator. Baseline receives only Planner/Implementer guidance.

The section states: original requirements and constraints > frozen task
specification > experimental variance guidance. It includes the condition,
profile ID, dimensions, common directive and only the current role's guidance.
It explicitly forbids changing the frozen decomposition, mandatory selectors,
accessible behavior, acceptance criteria, runtime constraints and sampling.
Existing user payloads and model configurations are unchanged. A control prompt
gets no added text, including no generic diversity reminder.

QA is explicitly excluded from prompt conditioning. Verification, QA schemas,
evidence grounding and deterministic acceptance are unchanged. QA still sees
the existing generated artifact and coordinated specification, which may reflect
the selected design; B2 does not attempt to blind those normal evidence inputs.

## B1, programmatic use and provenance

`load_variance_context(condition, workflow, base=...)` accepts B1's existing
`VarianceCondition` model or its dictionary with identifier, profile_path and
profile_hash. Resolve B1 paths against the plan's recorded reference_base. Hashes
use the existing `fingerprint` of raw parsed JSON, not normalized Pydantic output
or file bytes. Key order and whitespace formatting do not affect the hash;
adding an omitted default field does. Hash mismatch rejects the treatment.

Workflow inputs are `variance_condition`, `variance_profile` and optional
`variance_profile_hash`. CLI exposes these as hyphenated flags. For a single run
without an expected hash, the loader computes it and validates the snapshot.
Use the expected B1 hash (`--variance-profile-hash <64-hex>`) for frozen experiments.
There is no automatic selection or execution of candidates in B2.

Each run saves `variance_context.json`, containing the condition, profile ID/hash,
dimensions, exact profile JSON, applicable roles and exact appended system-prompt
sections keyed by role. The task-loader ledger hashes this artifact. Existing
`<role>_request.json` and stage ledgers preserve the actual requests; these identify
which configured roles were reached if generation fails partway through a run.
Control runs record null profile identity and empty roles/directives. Invalid
treatments use the existing failed-run diagnostics and do not call generation models.

## Scope and limitations

Profiles are advisory instructions, not a proof of model compliance or diversity.
Structural validation cannot establish that arbitrary prose is semantically
compatible with every task. The explicit authority rule and existing immutable
contract checks/verification remain responsible for handling generated results.
No sampling changes, new runtime, scheduler change or verification redesign is
introduced. No live generation was performed to validate B2; tests mock inference.

Files added: `agentic_web/variance.py`, the two example profiles,
`tests/test_variance.py`, and this report. Files modified:
`agentic_web/workflow.py`, `agentic_web/collaboration.py`,
`agentic_web/provenance.py`, `agentic_web/__main__.py`, and `README.md`.

Focused coverage compares original/control prompts, treatment-only suffixes,
both graphs, unchanged sampling and verification, frozen task/decomposition bytes,
invalid profiles and pinned hashes, B1 hash compatibility, exact artifact/ledger
provenance, QA exclusion and CLI forwarding. Tests use existing unittest conventions.

Results: focused B2 suite **10 passed, 16 subtests passed**. Complete regression
command `python -m pytest -q`: **269 passed, 229 subtests passed**, with one existing
Pydantic `TestCase` collection warning, in **77.40 seconds**.
