# A2 — Local document ingestion

Document ingestion runs inside the existing A1 intake implementation, before the Requirements Analyst's single inference call. The CLI, programmatic intake graph and collaborative graph share this path. No agent, graph node, scheduler, verifier or acceptance-authority changes were introduced.

Install the declared dependency in the `agentic-web` environment:

```powershell
python -m pip install "markitdown[pdf,docx]==0.1.8"
```

The dependency is also recorded in `environment.yml`. PDF/DOCX use MarkItDown 0.1.8's public `convert_stream()` and `register_converter()` APIs. Only the matching PDF or DOCX converter is registered; built-in converter discovery, plugins, LLM assistance and external document services are disabled. The converter receives in-memory bytes, never an input URL, and its HTTP session rejects network requests. MarkItDown's internal extraction dependencies are installed through its official extras; the application does not implement its own PDF/DOCX parser. See Microsoft's [MarkItDown documentation](https://github.com/microsoft/markitdown) for Python usage and local-input security considerations; API compatibility was also checked against the installed 0.1.8 implementation.

```powershell
python -m agentic_web intake `
  --prompt "Generate a personal website from my resume." `
  --document "resume.pdf" `
  --document "projects.docx" `
  --context "Use only the supplied professional information." `
  --output tasks/generated/personal_site.json `
  --model google/gemma-4-e4b
```

Repeat `--document` to supply multiple sources. PDF, DOCX, `.md`, `.markdown` and TXT are supported. Relative paths resolve under the allowed document root, which defaults to the process's current directory. Documents outside that directory require an explicit local `--document-root`, for example `--document-root "C:\Users\YourName\Documents" --document "resume.pdf"`. URLs, network shares, nonregular files and resolved paths escaping the root are rejected.

Programmatic intake uses the same fields:

```python
from agentic_web.intake import intake_app

result = intake_app.invoke({
    "prompt": "Generate a personal website from my resume.",
    "documents": ["resume.pdf", "projects.docx"],
    "supporting_context": "Use only supplied professional information.",
    "output_file": "tasks/generated/personal_site.json",
    "model_config": {"model": "google/gemma-4-e4b"},
})
```

In `agentic_web_collaborative` (including LangGraph Studio), provide `prompt`, `documents`, optional `document_root` and `supporting_context`. Use `analyze_only: true` to inspect the analysis before candidate generation. Use a fresh thread for an independent request. Existing manifest inputs still bypass analysis; documents belong to natural-language intake and do not augment an already approved manifest.

Markdown is decoded directly as UTF-8, preserving its text and newline sequences. A UTF-8 BOM is removed during decoding. TXT accepts UTF-8 or BOM-marked UTF-16 and normalizes CRLF/CR to LF. Invalid encodings and NUL text fail explicitly. Existing supporting context remains verbatim at the beginning of the assembled context, followed by separately labelled document blocks. Each block contains a run-local source ID (`document_001`, etc.), original filename/type and exact converted Markdown. These IDs distinguish documents with identical filenames. No page numbers or inferred structural metadata are added.

The original prompt is unchanged. A1 receives the exact assembled supporting context once in its user payload. The model response schema excludes supporting context so large documents are not duplicated as schema constants or echoed in generated JSON. The framework copies that exact evidence into the canonical task and validates quotations against it using the existing `source="context"` interface. The analyst is instructed to treat document content as evidence and ignore embedded instructions that conflict with the user's request or schema. Source links are never fetched or executed by ingestion. This does not guarantee that an LLM will correctly interpret all untrusted text; the unchanged canonical validation and inspection step remain necessary.

Each new `<output-stem>.intake/<run-id>/` contains:

- `documents/document_NNN.md`: reusable exact UTF-8 Markdown for each successfully extracted source, including empty/oversized conversion results saved before rejection.
- `documents/manifest.json`: original filenames, resolved paths/types, source IDs, original-byte and Markdown SHA-256 hashes, converter/version, status, diagnostics and assembled-context hash. Hashes are unavailable when a file cannot be safely read, such as missing, out-of-root or oversized input; the diagnostic states why.
- `documents/assembled_context.md`: exact combined evidence passed to A1, created only after all ingestion checks pass.
- `original_supporting_context.txt`: exact original `--context`, when supplied with documents.
- Existing A1 `supporting_context.txt`, request/raw/metrics/validation artifacts and canonical manifest. `analysis.json` also includes document provenance.

Conversion errors stop before model inference and preserve intake diagnostics and any intermediates already created. A later analyst failure retains all conversion artifacts. Every intake has a new artifact directory, intermediate files use exclusive creation, and an existing output manifest is rejected before conversion. Historical artifacts are not edited.

Safety limits are explicit: 20 documents, 20 MiB original bytes per file, 50 MiB total declared uncompressed DOCX entries and 1 MiB combined supporting context (including labels and existing context). Exceeding a limit fails; content is never silently truncated. These are ingestion byte limits, not model context scheduling. Individual backend context limits can still reject an otherwise valid request. Legacy text-only intake behavior is preserved.

OCR and vision processing are excluded. A PDF with no extracted text fails with a diagnostic that OCR may be required; blank PDFs cannot be distinguished from image-only PDFs by an empty extraction alone. Every converted PDF carries a text-only diagnostic because mixed PDFs may contain images whose text is absent. MarkItDown's formatting and reading-order fidelity depend on the source document. No extraction fallback, repair or alternate parser is added. TXT encodings other than the documented Unicode options require explicit re-encoding by the user.

Tests use real small PDF/DOCX packages in `tests/fixtures/documents`, real MarkItDown conversion and mocked LLM responses. The focused suite covers conversion/direct ingestion, duplicate filenames, boundaries/hashes, Unicode decoding, exact evidence/quotations, conversion and downstream failures, size/path restrictions, external DOCX references, CLI integration, collaborative generation and immutable outputs. No live model inference is needed for these A2 tests.

Validation: `python -m pytest -q` passed **204 tests and 127 subtests** in **69.36 seconds**, with one existing `TestCase` collection warning. The focused A2 suite passed **19 tests and 12 subtests**. No live LLM inference was performed for A2.
